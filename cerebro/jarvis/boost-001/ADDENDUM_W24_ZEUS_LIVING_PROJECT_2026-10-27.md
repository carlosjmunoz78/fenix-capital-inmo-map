## W24 · ZEUS LIVING PROJECT

### Mission
ZEUS must appear inside JARVIS as a permanent, resumable, continuously updated Work-style project.

It is not a static dashboard and not merely documentation. It is the living operational project through which Carlos, Jarvis, DeepSeek and authorised agents inspect, understand, build, repair, improve and verify ZEUS over time.

### JARVIS integration
JARVIS View 0 must expose a permanent project named **ZEUS**.

Opening ZEUS restores current context without rebuilding discovery from scratch.

The Work-style experience must include:
- persistent project context;
- conversation with Jarvis;
- durable tasks/jobs;
- files/artifacts/evidence;
- activity timeline;
- objectives/workstreams;
- blockers/HUMAN_REQUIRED;
- costs;
- previews/interfaces;
- links to code/routes/contracts/tests;
- resumable history;
- natural voice/text continuation.

### Living system model
ZEUS consumes the canonical W23 ZEUS Control Map rather than maintaining a separate manual model.

It should expose, where authorised:
- ZEUS domains/subsystems;
- CEREBRO OS and its engines/capabilities;
- JARVIS;
- interfaces: JARVIS, Work, Neural, technical and other discovered views;
- Browser and device-control layers;
- APPFACT-001;
- Social and SEO departments;
- agents/subagents;
- companies and business contexts;
- repositories/branches/deploy anchors;
- dependencies/reverse dependencies;
- contracts/tests/gates;
- environments;
- integrations/runbooks;
- incidents/health/status;
- current projects/work items;
- changes since the last verified state.

### Continuous editing model
Verified changes anywhere inside ZEUS must update the living project through events/generation where possible.

Examples:
- new CEREBRO engine -> appears in ZEUS;
- new agent/subagent -> appears under its department/ownership;
- Browser change -> routes/dependencies/tests update;
- APPFACT creates an application -> new project/build lifecycle appears;
- test/gate changes -> health/evidence update;
- deployment promotion/rollback -> timeline/environment state update;
- new company/system -> appears in ZEUS hierarchy after registration;
- interface change -> preview/evidence linked.

### Coordinated views
The same ZEUS project is rendered through multiple views:
1. **JARVIS** — conversational/executive Work-style surface.
2. **WORK** — detailed tasks, files, artifacts, previews and execution workspace.
3. **NEURAL** — visual graph of ZEUS domains, CEREBRO, agents, dependencies, jobs and health.
4. **TECHNICAL** — code/routes/contracts/tests/evidence drill-down.
5. **TIMELINE** — changes, incidents, promotions, rollbacks and learning.

All views use canonical Gateway/Jobs/Events/Registry/Map contracts rather than private client-only state.
