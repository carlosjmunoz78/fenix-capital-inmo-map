# CEREBRO OS · MULTI-AGENT PRESERVATION CONTRACT

## Canonical rule
CEREBRO is and remains a multi-agent / multi-subagent system. JARVIS BOOST 001 must not collapse specialised agent structures into a small monolithic set of generic agents.

## Preserve before changing
Existing agents, subagents, departments, orchestrators, workflows, knowledge domains, skills and engines are preserved unless evidence proves a specific element is redundant, broken, unsafe or objectively inferior.

Required sequence for any consolidation or replacement:
CONSERVAR -> ENTENDER -> ENVOLVER -> PROBAR -> MEJORAR -> MIGRAR.

No deletion/replacement without inventory, dependency map, current contract, backup/snapshot, behaviour tests, parallel candidate, PREPROD, OLD-vs-NEW comparison and tested rollback.

## Shared infrastructure does not mean fewer specialists
Shared components such as Browser Control Plane, Vault/IAM, Knowledge Broker, Router, Runtime, Events/Jobs, Observability and Factory are common infrastructure used by many agents. They do not replace the specialised agents that depend on them.

A Social Core means shared primitives and governance while preserving/creating network-specific departments, agents and subagents where useful. Facebook may be the structural reference pattern, but Instagram, LinkedIn, TikTok, X, YouTube, Pinterest and future networks retain specialised knowledge, procedures, roles and tests.

An SEO shared architecture means common runtime, knowledge access, evidence and orchestration while preserving/creating specialised agents and subagents for technical SEO, keyword research, content, local SEO, GSC, competitors, links, conversion, AI visibility, QA and other required domains.

## Knowledge model
Do not copy all knowledge into every agent. Keep specialised agents but provide layered retrieval:
- global CEREBRO knowledge;
- company knowledge;
- department knowledge;
- specialist knowledge;
- task/session context.

Agents receive only the authorised and relevant context they need. This reduces cost and stale duplication without reducing the number or specialisation of agents.

## Engine vs agent
An engine is not automatically an agent and an agent is not automatically an engine. Do not merge or delete either category merely because names overlap. Audit responsibilities, contracts, tools, permissions and evidence before proposing any consolidation.

## DeepSeek instruction
DeepSeek must first inventory the actual agent/subagent topology and classify each node as KEEP, WRAP, ENRICH, REPAIR, MERGE_CANDIDATE or RETIRE_CANDIDATE. MERGE_CANDIDATE/RETIRE_CANDIDATE are proposals only and require dependency/evidence/OLD-vs-NEW gates before any implementation.

Default classification for an unverified existing agent/subagent is KEEP_PENDING_AUDIT.

## Success condition
After BOOST-001, CEREBRO may have the same, more or fewer logical agents only where evidence justifies it. The goal is not agent-count reduction. The goal is a stronger specialised multi-agent organism with shared infrastructure, correct knowledge, clean orchestration and verified execution.
